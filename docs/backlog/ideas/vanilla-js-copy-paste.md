# GooseUI на HTML и ванильном JS: копируй и вставляй

#p2 #feature #docs

## Описание

Сейчас компоненты ставятся только в React (shadcn CLI). Нужна версия, которую можно просто скопировать в любой проект без фреймворка: Astro, Laravel, Rails, Django, обычный HTML. Устанавливать ничего не нужно, копируешь разметку, CSS и небольшой скрипт.

Основа для этого уже есть: компоненты сделаны на нативном HTML и CSS (`<details>`, `<dialog>`, `popover`, радиокнопки с `:has()`), а около 40% реестра не отправляют в браузер ни строчки JavaScript. В них React нужен только как шаблон разметки.

Статус: обсуждаем, пользователь ещё не утвердил (2026-11-25).

## Что хочется

- [ ] На docs-странице компонента вкладка «HTML» рядом с React: готовая разметка с Tailwind-классами и кнопка «Копировать».
- [ ] Для компонентов с поведением отдельный маленький скрипт на ванильном JS, который цепляется к `data-*` атрибутам (как у Preline): вставил `<script>` или модуль, и всё работает. Без зависимостей и сборки.
- [ ] Цвета и тема те же: CSS-переменные shadcn, тёмная тема через класс `.dark`.
- [ ] Вариант без Tailwind (обычный CSS) — решить позже, нужен ли.

## Варианты устройства (решить)

1. **Отдельные HTML-версии рядом с React.** Быстро начать, но разметку придётся поддерживать в двух местах.
2. **Общее ядро.** Разметка и скрипт на ванильном JS — первоисточник, React-компонент — тонкая обёртка над ними. Меньше расхождений, но нужен рефакторинг реестра.
3. Позже, если зайдёт: Vue и Svelte через реестры shadcn-vue и shadcn-svelte (тот же формат `registry.json`, отдельная сборка `/r/vue/*.json`).

Не подходит:
- Web Components: Shadow DOM плохо сочетается с Tailwind и темами shadcn, слабый SSR.
- Автоконвертеры (Mitosis): код низкого качества.

## Задачи для реализации

- [ ] Пилот: вкладка «HTML» и копирование для 5 компонентов без JS — Accordion, Tabs, Switch, Hint, Marquee.
- [ ] Пилот с поведением: 1–2 компонента с ванильным скриптом на `data-*` (например, Dialog и Copy Button).
- [ ] Решить между вариантами 1 и 2 по итогам пилота.
- [ ] Генерация HTML из React-компонентов при сборке (renderToStaticMarkup), чтобы не писать разметку руками.
- [ ] Страница «Использование без React» в документации.
- [ ] Раздел «Фреймворки» по образцу https://preline.co/docs/frameworks.html (см. ниже).

## Гайды по стекам (как у Preline)

Пример: https://preline.co/docs/frameworks.html — сетка карточек (логотип, название, одна строка), две секции: «Установка» и «Особенности стека».

Стеки (порядок карточек):
- Фронтенд: HTML + Vite, React + Vite, Next.js, Vue, Nuxt, Angular, Astro, Svelte/SvelteKit, SolidJS, Qwik, Remix / React Router.
- Бэкенд и full-stack: Laravel (Blade), Livewire, Inertia, Symfony (Twig), Rails (Hotwire/Turbo), Phoenix LiveView, Django, Flask, Express, Hugo, ASP.NET Core / Blazor, Ember.

Одна страница гайда, единый шаблон:
1. Проверенная версия стека и ссылка на живой пример (playground / репозиторий-стартер).
2. Установка: Tailwind v4 + токены GooseUI (CSS-переменные shadcn, `.dark`), куда положить `globals.css`.
3. Подключение скрипта GooseUI (ванильный JS): тег `<script type="module">` или импорт во входной точке (Vite entry, `app.js` у Laravel, клиентский компонент в Next.js).
4. Повторная инициализация после клиентской навигации и частичных обновлений: Next.js (`pathname`), Turbo (`turbo:load`), Livewire (`livewire:navigated`), HTMX (`htmx:afterSwap`), Astro (`astro:page-load`), SPA-роутеры. Если скрипт построен на делегировании событий от `document` и `MutationObserver`, этот шаг почти не нужен — заложить так в архитектуру.
5. Тёмная тема: переключение класса `.dark` и запоминание без мигания.
6. Частые проблемы и чеклист.
7. Ссылки на соседние гайды.

Начать с 4 гайдов: HTML + Vite, Next.js, Astro, Laravel. Остальные — по запросам.
